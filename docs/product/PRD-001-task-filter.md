# PRD-001：任务看板筛选与状态记忆

## 1. 背景

测试任务数量增加后，用户需要快速定位某个需求，或只查看特定状态的任务。当前看板只能展示完整列表。

## 2. 目标

在不增加后端写入和第三方依赖的前提下，为任务看板增加关键词筛选、状态筛选和 URL 状态记忆。

## 3. 用户故事

作为测试人员，我希望按需求编号、标题和状态筛选任务，并在刷新页面后保留筛选条件，以便持续观察同一组任务。

## 4. 功能需求

1. 页面在“需求列表”上方显示关键词输入框、状态选择框和“清除筛选”按钮。
2. 关键词匹配任务编号或标题，忽略大小写，并忽略首尾空格。
3. 状态支持：全部、待处理、进行中、已完成。
4. 关键词与状态条件同时存在时采用 AND 关系。
5. 筛选结果数量实时更新。
6. 无匹配结果时显示明确的空状态，而不是空白区域。
7. 将非空关键词写入 URL 参数 `q`，将非“全部”的状态写入 `status`。
8. 页面刷新或复制 URL 后能够恢复筛选条件。
9. 未知的 `status` 参数按“全部”处理，并从 URL 中移除。
10. “清除筛选”恢复完整列表并删除相关 URL 参数。

## 5. 非功能要求

- 控件必须有可访问名称，并可使用键盘操作。
- 不修改 `/api/tasks` 的数据结构。
- 不增加数据库、认证、遥测或第三方运行时依赖。
- 保持窄屏可用。

## 6. 不在范围内

- 服务端筛选、分页和排序；
- 新增、编辑或删除任务；
- 用户账号和跨设备同步；
- 部署和生产环境配置。

## 7. 验收标准

- 上述十条功能需求均可复现；
- `npm test` 退出码为 0；
- 为纯筛选逻辑和 URL 参数处理增加自动测试；
- 浏览器控制台无新增错误；
- 只修改约定的 Change Boundary。
